A quick setup.
Then it’s all yours.

This release installs as an unpacked extension, outside the Chrome Web Store. No coding needed.

  1. 1

    Download & extract

    Unzip the download into a folder you’ll keep. Install only one build at a time.

  2. 2

    Enable Developer mode

    Open chrome://extensions in Chrome and switch on Developer mode.

  3. 3

    Load the extension

    Click Load unpacked and choose the extracted folder containing manifest.json.

  4. 4

    Meet your Tokens tab

    Reload your website and open TokenLens from Chrome’s toolbar. If needed, click Connect this site or Connect page inspector. When the popup says Inspector ready, close it, open DevTools and select Tokens (check the » menu). If DevTools was already open during installation, close and reopen it.

A FEW GOOD QUESTIONS

Before you
pick your first pixel.

Read the documentation
How do I update my unpacked installation?+

Download v0.1.3 using the same build you already have: standard or per-site permissions. Extract it into your existing extension folder, replacing the old files. In chrome://extensions, click TokenLens’s Reload button. Reload the website you want to inspect, then close and reopen DevTools. The popup footer shows your installed version. Export any edits you want to keep before updating.

The popup says Connected. Where is the editor?+

The popup checks site access and connects the page inspector. The editor is in Chrome DevTools. Close the popup, right-click the webpage and choose Inspect, then open the Tokens tab or find it in the » menu. Connecting a site does not open DevTools automatically. If the tab is missing after installing or updating, close and reopen DevTools.

What if the editor shows a recovery screen?+

Your session has not been reset. Use Save session JSON to back up all edits, or Save CSS for exportable overrides, before reloading. Then choose Retry editor and pick an element again. If the problem returns, open Error details and report it through the issue link.

Does TokenLens change my website’s source code?+

No. Live previews use a separate stylesheet in the inspected page. Revert an edit to remove the override. Export CSS when you’re ready to apply your changes to a project; TokenLens doesn’t write to your source files.

What happens to my edits when I leave a page?+

Edits survive closing and reopening DevTools for the current document. Navigation starts a new document session. Export a JSON session to save your work, or take a CSS stylesheet with you.

Can I inspect any website?+

TokenLens works on ordinary web pages where you’ve granted it access. Chrome’s internal pages, the Chrome Web Store, closed shadow roots, and canvas or video pixels aren’t available as ordinary DOM elements. Frame and open shadow-root support depends on access and page structure.

How accurate is token detection?+

Computed values come from Chrome. Tracing a value back to its token and source is best-effort: unreadable stylesheets and advanced CSS can leave gaps. A “Partial source trace” badge means some CSS source or token-alias attribution could not be verified. It summarizes the inspected stylesheet scope, so a warning can come from a rule unrelated to the selected element. It does not mean every token is wrong or the site failed to connect. Open the diagnostics for the specific limitations. Live computed values remain available, and consumer counts are estimates. Component details describe the rendered DOM, rather than React or Vue source components.

Does my page data leave my browser?+

There’s no account, telemetry, or hosted analysis service. Inspection and session storage happen locally. To recover unreadable CSS, TokenLens may request a stylesheet from its original URL without credentials. Exported files can contain page URLs, selectors and token values, so review them before sharing.
