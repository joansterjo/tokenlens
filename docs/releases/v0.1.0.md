# TokenLens 0.1.0

Built by [Joan Sterjo](https://github.com/joansterjo).

TokenLens brings design-token inspection and live editing to Chrome DevTools. Pick an element, follow its token aliases and declaration sources, change colors, typography, spacing or shadows, and export a reusable CSS override.

## Download and install

- **tokenlens-0.1.0.zip** — standard build with access to supported pages.
- **tokenlens-0.1.0-optional-permissions.zip** — enable individual sites using **Connect this site** in the toolbar popup.
- **SHA256SUMS** — SHA-256 checksums for both ZIP files.

Extract a ZIP, open `chrome://extensions`, enable **Developer mode**, and choose **Load unpacked**. Select the extracted folder containing `manifest.json`, reload your website, and open the **Tokens** tab in DevTools. No build tools are required. Install only one build at a time.

This is an unpacked extension release, not a Chrome Web Store publication. The manifest requires Chrome 120 or newer; the verification report lists the browser versions actually tested.

## Included

- Element picking and inspection of CSS custom properties, alias chains, computed values and provenance.
- Visual color editing, a screen eyedropper where supported, typography and shadow controls.
- Global, selector and element edit scopes with live preview, undo, redo and revert.
- Component metadata, box model, layout, attributes and approximate accessibility information.
- On-demand page audits with JSON and CSV exports.
- CSS override export, DevTools Local Overrides guidance, and JSON session import/export.
- Local processing, no account, no telemetry. Stylesheet recovery may request CSS from its original URL without credentials.

## Verification and limits

The initial build passed 80 Node tests, 54 real-browser tests and 14 extension/platform/performance tests. Production bundles passed the configured size limits, and both downloadable archives were checked for integrity and required entry points.

Token provenance and consumer counts are best-effort. Advanced CSS, unreadable stylesheets and some shadow-root cases can limit attribution or export fidelity. Native permission prompts, docked/undocked EyeDropper behavior and bulk declaration-editor paste still need manual verification.

See the [README](https://github.com/joansterjo/tokenlens#readme), [verification report](https://github.com/joansterjo/tokenlens/blob/main/docs/verification.md) and [export guide](https://github.com/joansterjo/tokenlens/blob/main/docs/export-targets.md) for details.
