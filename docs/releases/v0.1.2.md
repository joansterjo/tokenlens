# TokenLens 0.1.2 — Consistent versioning and update guidance

Built by [Joan Sterjo](https://github.com/joansterjo).

TokenLens 0.1.2 keeps the installed extension, release downloads and exported CSS aligned on the same version. It includes the connection and editing fixes from 0.1.1, with clearer installation and update instructions.

## Changed in 0.1.2

- The manifest, extension UI and CSS export header read their version from `package.json`. A release-content check verifies current documentation and website download links before packaging or deployment.
- CSS exports identify the current version instead of keeping the old `0.1.0` header.
- The README, product page and download instructions point to the current release and explain where the editor lives: **DevTools → Tokens**.
- Update instructions explain how to replace an unpacked installation, reload the extension and page, reopen DevTools, and verify the installed version.

## Included from 0.1.1

- The popup checks the active site and shows access permission, inspector readiness and the installed version. Connection success waits for the inspector to be ready; failures show actionable guidance.
- Per-site permission requests happen directly from the Connect button's click.
- Onboarding guides you from the connected popup to the **Tokens** tab, including the **»** menu and reopening DevTools after installation or an update.
- Tokens picks up the element already selected in Elements, recovers a missing inspector, and follows selections inside frames.
- Source confidence uses **Partial source trace** and **Estimated source trace** with an explanation of what remains uncertain.
- Editors and palette colors use the browser's computed values when reconstructed declarations disagree. Authored values and alias chains remain available in source details.

## Download and install

- [tokenlens-0.1.2.zip](https://github.com/joansterjo/tokenlens/releases/download/v0.1.2/tokenlens-0.1.2.zip) — standard build with access to supported pages.
- [tokenlens-0.1.2-optional-permissions.zip](https://github.com/joansterjo/tokenlens/releases/download/v0.1.2/tokenlens-0.1.2-optional-permissions.zip) — connect sites individually from the toolbar popup.
- [SHA256SUMS](https://github.com/joansterjo/tokenlens/releases/download/v0.1.2/SHA256SUMS) — checksums for both ZIP files.

For a new installation, extract one ZIP, open `chrome://extensions`, enable **Developer mode**, choose **Load unpacked**, and select the extracted folder containing `manifest.json`. Reload the website, open DevTools and choose **Tokens** from the tab bar or **»** menu. With the per-site build, connect the site through the toolbar popup first.

The popup connects the page; the editor is in **DevTools → Tokens**. Connecting does not open DevTools automatically. Close and reopen DevTools if Tokens is missing after installation.

## Update an existing installation

Unpacked extensions do not update automatically. Install only one build at a time.

1. Save any current edits you want to keep using **Save session**.
2. Download the same build you already use, extract it, and replace the contents of your existing extension folder. Keep its folder path unchanged.
3. Click TokenLens's **Reload** button in `chrome://extensions`.
4. Reload the website and close/reopen DevTools. Check that the popup footer shows **v0.1.2**, then choose **Tokens**. Reconnect the site if prompted.

Both ZIPs include `INSTALL.txt`. This is an unpacked extension release, outside the Chrome Web Store. The manifest requires Chrome 120 or newer; tested versions and remaining manual checks are documented in the [verification report](https://github.com/joansterjo/tokenlens/blob/main/docs/verification.md).

## Verification and limits

Token provenance and consumer counts remain best-effort. Advanced CSS, unreadable stylesheets and some shadow-root cases can limit attribution or export fidelity. This patch does not expand those resolver guarantees. Native optional-permission prompts, docked/undocked EyeDropper behavior and bulk declaration-editor paste still need manual verification.

See the [verification report](https://github.com/joansterjo/tokenlens/blob/main/docs/verification.md) for test results and the [export guide](https://github.com/joansterjo/tokenlens/blob/main/docs/export-targets.md) for preview/export behavior.
