# TokenLens 0.1.3 — Color crash fix and editor recovery

Built by [Joan Sterjo](https://github.com/joansterjo).

This patch fixes a reproduced blank-panel crash when a selected color contains missing CSS components. It also gives the editor a recovery screen with retry and backup controls, so a rendering failure does not silently discard the current edit session.

## Fixed

- Valid values such as `oklch(0.5 none none)` could leave chroma undefined in the color parser. Formatting that component in the color editor threw an error and blanked the React panel. Missing components are now normalized to finite working values for rendering and conversion, while the original authored CSS text is preserved.
- An editor error boundary catches rendering failures and displays **Retry editor**, **Save session JSON**, **Save CSS** and error details. Retry clears the failed view and retains edits and history; you can then pick an element again.
- Reading or writing the saved theme preference can fail in restricted storage environments. Those operations are now guarded so the editor can continue rendering.

The connection, onboarding, computed-value and version consistency fixes from earlier releases are included.

Validation: 93 Node tests, 84 real-browser tests and 16 extension/platform/performance tests passed, including picking, editing, exporting and reverting a missing-component color in the packaged DevTools panel. Typecheck, lint, both extension builds and bundle-size budgets passed.

## Download and install

- [tokenlens-0.1.3.zip](https://github.com/joansterjo/tokenlens/releases/download/v0.1.3/tokenlens-0.1.3.zip) — standard build with access to supported pages.
- [tokenlens-0.1.3-optional-permissions.zip](https://github.com/joansterjo/tokenlens/releases/download/v0.1.3/tokenlens-0.1.3-optional-permissions.zip) — connect sites individually from the toolbar popup.
- [SHA256SUMS](https://github.com/joansterjo/tokenlens/releases/download/v0.1.3/SHA256SUMS) — checksums for both ZIP files.

For a new installation, extract one ZIP, open `chrome://extensions`, enable **Developer mode**, choose **Load unpacked**, and select the extracted folder containing `manifest.json`. Reload your website, open DevTools and choose **Tokens** from the tab bar or **»** menu. With the per-site build, connect the site through the toolbar popup first.

The popup connects the page. The editor lives in **DevTools → Tokens**; connecting does not open DevTools automatically. Both ZIPs include `INSTALL.txt`.

## Update an existing installation

Unpacked extensions do not update automatically. Install only one build at a time.

1. Save edits you want to keep before updating. If the recovery screen is available, use **Save session JSON** or **Save CSS** there.
2. Download the same build you already use, extract it, and replace the contents of your existing extension folder. Keep its folder path unchanged.
3. Click TokenLens's **Reload** button in `chrome://extensions`.
4. Reload the website and close/reopen DevTools. Confirm **v0.1.3** in the popup footer, then choose **Tokens**. Reconnect the site if prompted.

## Recovery and limits

If the recovery screen appears, back up your edits before closing DevTools or reloading the page. JSON includes all current edits; CSS retains the usual warnings and exclusions for edits that a stylesheet cannot reproduce. Choose **Retry editor**, then select an element again. If the problem returns, open **Error details** and report it through the issue link.

The missing-component crash is a confirmed reproduction. The original reported private page's error stack has not been observed, so this patch is not confirmation that every possible blank-panel cause is resolved. Error recovery is for caught editor rendering failures; it does not recover a closed or crashed browser process.

Token provenance and consumer counts remain best-effort. Advanced CSS, unreadable stylesheets and some shadow-root cases can limit attribution or export fidelity. Native optional-permission prompts, docked/undocked EyeDropper behavior and bulk declaration-editor paste still need manual verification.
